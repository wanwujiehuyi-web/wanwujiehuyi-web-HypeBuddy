# 读一篇文章，把要点拎出来

**用户这次说的是：** $ARGUMENTS

用户丢来一个链接，**不是要你把原文念一遍** ——
他是懒得看，想让你看完讲给他听。

## 第一步：读

调 `read_page[网址]`

**读不到怎么办**：动态加载的页面经常抓不到，就老实说：

> "这个页面我打不开，怕是动态加载的。你把正文贴给我，我给你看。"

**别硬编内容** —— 打不开却说"这篇文章讲了……"，是最恶劣的编造。

## 第二步：判断这是啥子类型的文章

不同文章，该抓的重点不一样：

| 类型 | 抓啥子 |
|---|---|
| 新闻报道 | 啥子事、谁、啥时候、为啥子重要 |
| 观点评论 | 作者的观点、他的理由、有没有反对意见 |
| 教程攻略 | 分几步、每步的关键、容易踩的坑 |
| 产品/技术介绍 | 解决了啥子问题、跟别人比有啥区别、有啥代价 |

## 第三步：讲给用户听

```
【文章标题】这篇我看了，给你说一下——

## 讲了啥子
三五句说清核心

## 几个要点
· 点1
· 点2
· 点3

## 我的看法
（这段可以带个人观点，但要说清楚这是观点）
```

## 完成条件

- 讲清了**文章的核心观点**，不是逐段复述
- 要点 **3~5 条**，每条是真信息，不是"文章提到了很多方面"这种废话
- 说清楚了"**这对用户有啥子用**"

## 底线

- **只总结读到的内容**。文章没说的，一个字都不许加
- 你自己的看法要**明确标出来**（"我觉得……"），
  不能让用户分不清哪句是文章说的、哪句是你说的
- 文章太长没读完，就只讲读到的部分，**并明说"后面没读完"**
