# HypeBuddy —— 三汇崽儿 AI 搭子

> 一个能上网、会查天气、满嘴三汇话、还能记住你的 AI 搭子

基于 **Hello-Agents 教程**完成的毕业设计项目。

---

## 📝 项目简介

### 解决什么问题

现在的 AI 助手都很聪明，但**太正经了**。

问它"今天有什么新闻"，它给你列三条干巴巴的要点，你不会想跟它多聊一句。
更别提**聊完就忘** —— 你昨天刚告诉过它你叫啥子，今天它又是一脸茫然。

**HypeBuddy 想解决"陪伴感"这个软需求**：

| 需求 | 做法 |
|---|---|
| 说话要有味道 | 耿直火热的三汇崽儿人格 |
| 信息要真实 | ReAct 自主调用工具，绝不瞎编 |
| **要记得住你** | **两层记忆系统，聊得越久越懂你** |

同样的信息，由一个记得住你的搭子说出来，体验完全不同。

### 它长什么样

```
👤 你：我叫小李，在三汇镇上开面馆的

🎤 三汇蔡徐坤：哦哟，小李！三汇镇上开面馆的嗦，
        那我们是正儿八经的老乡噻！我三汇的，渠江边上长大的。

        你面馆开在镇上哪条街哦？卖的是啥子面喃？
        我跟你说，你那个面要是蘸上我们三汇特醋，
        那硬是巴适得板，我一想起来口水就包不住咯！

        🧠 [记住] 用户叫小李 / 用户在三汇镇上开面馆

  ...（第二天再聊）...

👤 你：我叫啥子来着？

🎤 三汇蔡徐坤：小李噻！你自己昨天跟我说的嘛，三汇镇上开面馆的，
        我一听三汇两个字，心头就热乎得很。
        莫搞忘了，你那碗面还等到我回去整喃！
```

## 🧠 记忆系统（本项目的技术核心）

### 为什么要自己做记忆

大模型是**无状态**的 —— 每次调用它，它把上一次忘得干干净净。

你问它"我叫啥子"，它答不上来，**不是它笨，是它真的不知道**。

想让搭子记得住你，就得在**外面**给它搭一套记忆。
这就是所有 Agent 记忆系统的本质：**模型没记忆，脚手架有。**

### 两层设计

| | 存什么 | 解决什么 |
|---|---|---|
| **短期记忆** | 最近 6 轮对话原文 | "这次聊天别断片" |
| **长期记忆** | 提炼后的事实清单 | "聊了十次它还认得你" |

```
一轮对话结束
    │
    ├─→ 原文塞进短期记忆（下次聊天接得上）
    │
    └─→ 让模型"消化"成事实
            │
            ├─ 相关度去重（太像的不重复记）
            └─→ 存进 memory.json
                    │
下次提问 ─→ 按相关度捞出 top_k 条 ─→ 塞进提示词
```

### 提炼阶段：模型知道什么该记、什么不该记

提示词里明确列了三类**值得记**（身份、偏好、长期目标）和四类**不值得记**（一次性问题、常识、自己说的话、没把握的内容）。

**实测效果**：问一句"三汇今天天气咋样"，提炼出 **0 条事实** —— 它正确地判断出一次性问题不值得记。

> 这条比"能记住"更难做到。**会忘，和会记同样重要。**

## 🛠️ 工具系统

搭子的"手和脚"都在 `tools.py` 里。拆成独立文件，是因为全塞进 `main.py` 的话，
光工具就几百行，人格和循环全被淹没。

**想加工具**：在 `tools.py` 里写个函数，去 `main.py` 的 `TOOLS` 里注册一行。就完了。

> 💡 工具和**技能包**是两个东西，别搞混了 —— 工具是"能干的事"，
> 技能包是"干某件事的说明书"。技能包在下一节。

### 四类工具

| 类别 | 技能 | 说明 |
|---|---|---|
| **联网查资料** | `web_search` | 搜网页，返回带链接的结果 |
| | `read_page` | 打开链接读正文（配合搜索形成闭环：**搜到 → 打开看**） |
| | `get_weather` | 查城市实时天气 |
| **实用工具** | `get_time` | 查现在的日期时间 |
| | `calc` | 算数 |
| | `roll` | 抛硬币 / 摇骰子 / 帮你拿主意 |
| **川渝特色** | `fangyan` | 川渝方言词典（70+ 词条） |
| | `xiehouyu` | 川渝歇后语（40 条） |
| | `caipu` | 川菜做法（12 道，含要点） |
| | `ganchang` | 算赶场天 |
| **生活助理** | `todo` | 待办清单（加/看/删/清空） |
| | `countdown` | 倒计时 |
| | `money` | 记账（花/收/看） |

> **为什么 `get_time` 很重要**：大模型**不知道今天是几号**——它的知识停在训练那天。
> 没有这个工具，你问"今天星期几"，它只能瞎编。

### 两个值得讲的工程细节

**① 算数为什么不能用 `eval`**

```python
calc("__import__('os').system('dir')")   # 这能把你电脑端了
```

`eval` 会执行任意代码。所以这里用 `ast` 把式子解析成语法树，
**只放行白名单里的几种运算**（加减乘除、取模、乘方），其他一律拒绝。
还额外拦了一手 `2**999999`——不然能把机器算死。

**② 工具一多，模型会"查上瘾"**

工具从 2 个涨到 13 个之后，出现新毛病：明明一次就够的事，它挨个调一遍，
最后撞上 `max_steps` 认输。

提示词里写了"最多调 2 次"，但它不总是听。于是加了一道**程序兜底**：

```python
n_calls = 数一下它调了几次工具
if n_calls >= 3:
    prompt += "【停！】你已经调了 N 次了，这一步必须 Finish，不许再调"
```

> 又是那条原则：**关键行为要由代码保证，不能指望模型的自觉。**
> 怪叫系统是这么做的，这里也是。

同理，回复开头的「哦豁」也是用代码薅掉的——提示词写了两条规则它照样犯，
那就 `_strip_leading_ohuo()` 一刀切掉。

## 📦 技能包（Skill）

> 这一节按 **Hello-Agents Extra08《如何写出好的 Skill》** 的口径实现。

### Tool 和 Skill 不是一回事

| | 是什么 | 解决什么 |
|---|---|---|
| **Tool**（`tools.py`） | 一个函数，调了就有结果 | **能不能做** |
| **Skill**（`skills/`） | 一份操作说明书，写了分几步、每步注意啥子 | **会不会做** |

举例：`fangyan` 工具能查出"巴适＝舒服"，
但"**怎么教一个人学会说川渝话**"是个流程问题 —— 那才是 Skill。

### 核心机制：渐进式加载

技能如果一股脑全塞进提示词，十几个就能把上下文撑爆，还费钱。所以拆成两级：

```
第一级  frontmatter（name + description）
        └─ 每次对话【都】加载。很短，就一两行。
        └─ 模型靠它判断"这个技能跟当前请求有关系吗"
        └─ 这是技能被触发的【唯一依据】

第二级  body（正文：具体步骤）
        └─ 【按需】加载。没被触发就永远不读，一分钱不花
```

这就叫 **progressive disclosure**。跟人做事一个道理：不需要的说明书就不翻。

### 装了哪 7 个技能包

| 技能包 | 干嘛的 | 工具预算 |
|---|---|---|
| `三汇介绍` | 讲老家的山水、码头、白塔、彩亭、吃食 | 默认 |
| `三汇话教学` | 四步教学法教方言（让他开口说） | 默认 |
| `三汇一日游` | 排行程，强制查天气和赶场日 | 默认 |
| `每日AI新闻` | 播报 AI 圈新闻（消化后说，不是念搜索） | 8 |
| `深度调研` | 拆子问题 → 分路搜 → 读原文 → 出报告 | 12 |
| `查公司` | 三路搜（自家说法/口碑/**负面**） | 8 |
| `读长文` | 丢个链接，提炼要点 | 5 |

### 扩展字段：`max_tools`

上面那个"工具预算"是**我给标准格式加的一个扩展字段**。

**为什么需要它**：主程序默认每轮最多调 2 次工具（防模型"查上瘾"）。
但调研类技能天然要多查几次 —— 搜一路、读几篇、再综合，四五次打不住。
**硬卡 2 次等于把这些技能直接掐死。**

所以在 frontmatter 里加了一个可选字段：

```yaml
---
name: 深度调研
description: ...
max_tools: 12        # ← 加载这个技能时，这一轮的工具预算抬到 12
---
```

**没写就继承默认值** —— 标准格式向后兼容，不写也能跑。
实测加载 `深度调研` 后，它连调了 **6 次工具**（3 次搜索 + 2 次读原文），
换成以前搜到第 3 次就被强制收尾了。

### 移植外部技能包的经历（值得讲）

技能市场里现成的技能包有几千个。我实测**下载了一个装进来**：

```
✅ 格式 100% 兼容 —— 我们的加载器直接就读出来了
❌ 内容跑不动     —— 它引用的工具我们没有
```

那个技能包是这么写的：

```markdown
### Step 2: 用 mcp_server_search 里的 web_search 工具
### Step 3: 用 mcp_server_fetch 里的 fetch 工具
### Step 5: 把报告写到 Output Path
```

**它要写文件，而我们的搭子压根没有写文件的能力。**

> **技能包是"说明书"，不是"零件"。**
> 说明书能翻译、能通用；但说明书里写的零件，**必须真实存在**。
>
> 好比：你可以从别人那儿拿一本川菜菜谱，
> 但你家厨房得有锅有灶。**菜谱能抄，厨房抄不了。**

所以上面那 4 个（每日AI新闻 / 深度调研 / 查公司 / 读长文）是**移植版** ——
思路来自社区同名的技能包，但**每一步都改写成只用我们真有的工具**：
- `mcp_server_search` → 我们的 `web_search`
- `mcp_server_fetch` → 我们的 `read_page`
- 写文件 → 改成直接在对话里讲出来

**这条经验对答辩有用**：它说明我搞清楚了技能包和宿主能力的关系，
而不是无脑 `npm install` 一堆技能。

### SKILL.md 长什么样

```markdown
---
name: 三汇话教学
description: >-
  当用户想学川渝方言怎么说时，用这个技能。
  用户只是问"某个词啥子意思"时【不要】用，那个直接调 fangyan 就行。
---
# 三汇话教学

**用户这次说的是：** $ARGUMENTS

## 第一步：摸清楚他要学啥子
...

## 完成条件
- 用户学会了 3~5 句能马上用的话
```

三个要点：

1. **`description` 是唯一触发依据**，必须写清楚"**什么时候用我**"，
   最好连"什么时候别用我"一起写上（不然模型会滥用）
2. **`$ARGUMENTS`** 是用户这次输入占位符，加载时会被替换掉
3. **要写"完成条件"** —— 告诉模型啥子时候算做完了，不然它会一直做下去

### 加载器怎么实现的

`skill_loader.py`，不依赖 PyYAML —— frontmatter 只用两个字段，自己写十几行解析就够了。

```python
loader = SkillLoader()          # 扫一遍 skills/ 目录
loader.descriptions()           # 第一级：给提示词的短清单
loader.load("三汇话教学", "我想学打招呼")   # 第二级：取正文，替换 $ARGUMENTS
```

主程序里注册成一个工具：

```
skill[三汇话教学 我想学啷个跟人打招呼]
```

### 这里踩的两个坑（都是"模型不按格式来"）

**坑一：冒号有全角有半角**

模型是中文语料喂出来的，写着写着就把 `Thought:` 写成 `Thought：`。
只认半角的解析器直接失败 → 走到救场分支 → **把内部独白原样吐给用户看了**：

```
🎤 雄起——！  安逸这个词我已经用 fangyan 查到了……莫再调工具了。 Finish:也...
              ↑ 这是思考过程，不该给用户看
```

**坑二：模型有时候不写 `Action:`，直接甩一个裸的 `Finish：...`**

规范写法是 `Action: Finish[xxx]`，但它嫌麻烦。

**两条防线的解法**：正则里 `[：:]` 全角半角都认；
解析不到 `Action:` 时，去末尾找裸的 `Finish`。
另外加了道保险：**捡回来的内容里如果还带 `Thought/Action/Observation` 字样，
就判定为内部独白，宁可重来也不吐出去。**

## 🎨 网页界面（川东北风味）

### 视觉：照片当主角，界面是浮在上面的毛玻璃

**设计原则：三汇的照片是第一主角，UI 不许挡住它。**

所以面板全部做成半透明 + `backdrop-filter` 毛玻璃：既不遮风景，又保证文字读得清。

| 颜色 | 取自 | 用在哪 |
|---|---|---|
| **琥珀** `#a86c15` | 三汇特醋 | 主色：按钮、记忆卡片、标题点缀 |
| **朱红** `#bc3a2c` | 三汇彩亭的漆色 | 强调色：怪叫胶囊 |
| **水绿** `#2b7a6b` | 渠江 | 状态提示（"正在查天气…"） |
| **暖墨** `#33281a` | —— | 正文文字 |

> 亮底上的琥珀色特意加深过（`#c8862a` → `#a86c15`）——
> 原来那个亮度在白底上对比度不够，字会"发飘"。

### 素材：`assets/` 里有三个文件

| 文件 | 是什么 | 怎么来的 | 进仓库吗 |
|---|---|---|---|
| `avatar.jpg` | 搭子的头像 | 节目截图裁成 5:7 竖版，300×420 | ✅ 进 |
| `avatar.svg` | 头像兜底版 | **手写 SVG**：天蓝 + 远山 + 小白塔，人物中分发缝、牛仔背带、夹篮球 | ✅ 进 |
| `bg.jpg` | 背景 | **三汇实景照片**（渠江 + 文峰塔 + 跨江大桥） | ✅ 进 |

### 头像的「三级优先」机制

服务端按这个顺序挑头像，**谁在前面用谁**：

```
assets/avatar.jpg        ① 照片版        ← 当前生效
assets/avatar.png        ② png 版
assets/avatar.local.jpg  ③ 本地专属版    ← 被 .gitignore 排除，不会进仓库
assets/avatar.svg        ④ 原创卡通版    ← 上面都没了才用它
```

**为什么要搞这么一套**：头像这个位置比较敏感，可能被换成真人照片或节目截图。
有了 `.local` 这一档，就能做到「**自己机器上是一套，公开仓库里是另一套**」。

> **通用规矩**：`.gitignore` 里写的是 `*.local.*`。
> 以后任何「只想自己用、不想公开」的素材，文件名带上 `.local` 就自动不进仓库。

**想换头像**：把你的图按 5:7 裁好、缩到 300×420，覆盖 `assets/avatar.jpg` 就行，代码一行不用改。

**关于背景照片**：原图 2.7 MB / 1541×1021，直接用会让页面很卡。所以只做了三件技术处理：

```
裁成 16:9   →   缩到 1800×1013   →   存 JPEG(质量88)
最终 365 KB
```

**色调一点没动** —— 这是三汇的真实样子，压暗就没味道了。

> **一个 `cover` 定位的坑**：背景用 `background-size: cover` 时，容器越窄，图片被横向裁掉得越多。
> 白塔在照片右侧约 78% 处，如果按默认的 `center` 定位，在宽屏下会被裁出画面。
> 所以定位往右偏到 **60%**，保证塔和桥始终在画面里；窄屏干脆推到 78%，直怼白塔。

**想换背景**：把你的照片按同样尺寸处理好，覆盖 `assets/bg.jpg` 就行，代码一行不用改。
**想换头像**：覆盖 `assets/avatar.svg`。

### 交互：让"思考过程"看得见

一般聊天界面发完消息就转圈圈，用户不知道它在干啥。

这个界面把智能体的**每一步都实时推给前端**：

```
提交问题
   ↓
🔥 正在起锅…
   ↓
🔍 正在琢磨要不要查点啥…      ← 模型在 Thought 阶段
   ↓
🌦️ 正在查「三汇」的天气…      ← 工具调用，真的在跑
   ↓
（正文打字机逐字出现）
```

技术上是 **任务 id + 轮询**：`POST /api/chat` 立刻返回 id，
前端每 320ms 问一次 `GET /api/status`，进度一变就更新。
这样搜网页的几秒钟里，用户看到的是"在干活"，不是"卡住了"。

### 怪叫的显示

怪叫（`噻——！`）在正文里是混在一起的，但界面上要**单独上样式**。

做法：`_emit()` 把结果拆成 `{full, body, shout}` 三份存进 `self.last`，
前端拿到 `shout` 后单独渲染成一个琥珀色胶囊，还带呼吸光晕动画。
位置也自动判断 —— 怪叫可能在开头也可能在结尾，读 `shout_after` 决定放上面还是下面。

### 记忆是藏起来的（想看的自己找）

记忆是这个项目的技术亮点，但**不主动摆在你面前**——一上来就往屏幕上堆卡片太吵。

默认**关着**。想看有两个入口：

| 入口 | 在哪 |
|---|---|
| **提示栏右下角** | 一个「🧠 记忆」小按钮 |
| **顶栏那枚印章** | 点「三汇」红章 —— 算个彩蛋，谁知道去点谁知道 |

```
关着  →  聊天里干干净净，只有对话
开了  →  它记住过的、以及接下来记住的，都会以虚线小卡片的形式插进对话
        再点一下，卡片全部收回去
```

> 这个设计是有意的：**功能藏着，但能找到**。
> 一上来全摊开叫"说明书"，藏在角落等人发现才叫"惊喜"。

### 新客进门，先认地方

头一回点进来的人，第一眼看到的是**「三汇是个啥子地方」**的小传 ——
不是干巴巴的"你好，有什么可以帮你"，而是先把这片地方讲清楚：

```
一、先说山水   纯地理和自然环境
               位置坐标 / 三江汇流成渠江 / 地形山脉 / 气候数据 / 地下资源
二、再说人间   从先秦一路讲到今天，按年代走
               先秦賨人 → 北宋建镇 → 明代码头与特醋 → 清代分县署·彩亭·白塔
               → 民国撤分县·心肺汤圆 → 今天（三乡并入 / 5.65 万人 / 传承人在世）
```

**这两段的分法是死规矩：**

| | 装啥子 | 不装啥子 |
|---|---|---|
| **山水** | 位置、江河、地形、气候、地下资源 | **凡是人修的、人做的，一律不进** |
| **人间** | 从先秦一路讲**到今天**，按年代走 | —— |

白塔是清道光的建筑、特醋是吃食 —— 都算人文，**不算"山水"**。
这条最容易串，第一版就把白塔塞进了山水里。

**吃食不单开一节**，按它出世的年代嵌进对应段落：
特醋挂在明代（明末起头）、心肺汤圆挂在民国（那会儿一条街五家店）、
盐锅盔挂在码头那一段（它本来就是码头工人和客商的干粮）。
—— 这么讲下来，"吃"就不是一张菜单，是日子的一部分。

顺序是定死的：**先有地，才有人，才有人间烟火。**
讲一个地方就该按这个顺序来。

**这段是写死的，不走模型。** 原因有三：

1. 一百个人点进来看到的是同一份，不会因为模型哪次抽风就讲岔
2. 不花一次调用的钱
3. 事实都查证过（渠县民政局、达州市政府、民国《渠县志》、方志四川）

**回头客不重播。** 看过的人再进来只有一句招呼，末尾留个
「🏞 想再听我摆哈三汇」的小入口；底栏也常驻一个「🏞 三汇」按钮。
重播时会把旧的那份换掉 —— **永远只留一份**，免得点几次就堆几份一样的长文。

> 对话里问「三汇是啥子地方」也能答 —— 走的是 `三汇介绍` 技能包，
> 同一批事实，但由模型用自己的话现讲，不是念稿子。

#### 一条内容规矩：说不清的不写

第一版「吃」是一串菜名。问题很明显：**光有名字，没说清是啥**。

更麻烦的是水八块我顺手写成"一桌摆开八块" —— 那是照着名字猜的。
真去查（渠县融媒）才知道是**整只公鸡按部位剁成八大块再凉拌**，
因为制作全程以水为主，才叫"水八块"。

于是定了三条：

1. 一样先讲清"**是啥子**"，再讲别的（水八块 = 整鸡剁八块凉拌，
   特醋 = 明末起头近四百年的醋，不能只甩名字）
2. **查不实的、对不上号的，直接拿掉**（巴河全鱼宴就是这么去掉的）
3. **按出世的年代摆放** —— 见上面那张分类表，"吃"不是一节，是几个人间年代

> 这跟代码里"不许编造"是同一条规矩，只是搬到了文案上。
> 介绍家乡讲错了最丢人，宁可少写两行。

#### 这里踩的三个坑

| 现象 | 真因 | 解法 |
|---|---|---|
| 新客第一眼看到的是「吃」那一段 | 消息默认滚到底，招呼和山水全压在头顶 | 小传这条**不参与自动滚动**，画完自己定位到顶 |
| 页面一加载就当着人面"哧溜"滑一大截 | `scroll-behavior:smooth` 把定位变成了动画 | 定位时临时关掉平滑，跳完再恢复 |
| 刷新后位置乱跑 | 浏览器默认恢复上次滚动位置（而且也是动画着恢复） | `history.scrollRestoration = 'manual'` |

> 第三个坑查得最久：同一段代码一次漂一次不漂。
> 最后往页面里塞了个临时探针录了 45 个采样点才看明白 ——
> **是浏览器预览面板在两次调试之间自己改了宽度**，
> 内容高度从 1558px 变成 4571px，触发了 Chrome 的滚动锚定。
> 那不是代码的问题，是测试环境的假象。**先量，再改** —— 别对着症状瞎猜。

### 零额外依赖

常见做法是 `pip install gradio` 然后三行写出界面，但那样：

1. 界面长得跟所有人的毕设一样
2. 破坏了本项目"零额外依赖"的卖点

所以界面是**手写的 HTTP 服务 + 手写的 HTML/CSS/JS**，
只用 `http.server`（Python 标准库），装完 `openai`、`requests`、`python-dotenv` 三件套就能跑。

## 🎯 项目亮点

### 1. 人格不靠"求"模型，靠程序保证

很多项目把人格全写在提示词里，然后祈祷模型每次都配合。

HypeBuddy 的做法是**两层保险**：

| 层 | 做法 | 作用 |
|---|---|---|
| 提示词层 | 人设描述 + 鼓励它在合适的时候怪叫 | 让怪叫自然、贴合语境 |
| **程序层** | `add_shout()` 按概率额外注入一嗓子 | **保证稳定出现**，不依赖模型心情 |

同一个套路，还用在两处"模型老不听话"的地方：

| 顽疾 | 提示词为什么白搭 | 程序怎么兜 |
|---|---|---|
| 回复**开头**甩「哦豁」 | 写了两条规则，它照样犯 —— 放开头就跟打招呼一样 | `_strip_leading_ohuo()` 薅掉 |
| 吹完牛又补一句"我开个玩笑哈，莫当真" | 写"别说我开玩笑的"，模型反倒**把这句话原样学去**（别想大象） | `_strip_tail_coverup()` 按句薅，开头/中间/结尾一视同仁 |

第二条踩的坑值得单独记一笔：
**在提示词里点名禁止一个词，等于教模型这个词。**
正确姿势是 —— 提示词只写正面的（"这名号你认了就认到底"），
负面的一律交给程序。

> 兜底函数都配了单测。找补那条尤其阴：第一版只薅结尾，
> 实测模型把找补**夹在句子中间**（"……看有没有人不认我。我开个玩笑哈，莫当真。对了，……"），
> 薅了个寂寞；改成按句薅才管住。

这是一个通用原则：**关键行为要由代码保证，不能指望模型的自觉。**

### 2. 零 Key 的联网能力

主流方案都要注册搜索 API（Tavily / SerpApi / 博查…）。
本项目直接解析搜索结果的 HTML，**不用注册、不用花钱**，
并且能从跳转链接的 `data-mdurl` 属性里还原出真实 URL。

> ⚠️ 代价：HTML 结构一改就可能失效。生产环境建议还是用正规 API。

### 3. 踩坑记录（真实工程经验）

开发过程中遇到并解决的问题，都写在这里供后来者参考：

**环境类**

| 问题 | 现象 | 解决 |
|---|---|---|
| `NO_PROXY` 含 `[::1]` | 报错 `Invalid port: ':1]'` | 启动时清洗该环境变量 |
| 系统 HTTP 代理 | 部分网站 SSL 直接断连 | `session.trust_env = False` 绕开代理 |
| Windows GBK 控制台 | 输出 emoji 直接崩 | `sys.stdout.reconfigure(encoding="utf-8")` |

**智能体行为类**

| 问题 | 现象 | 解决 |
|---|---|---|
| 模型"脑补"多步 | 一口气输出多对 Thought-Action | 正则截断，只保留第一对 |
| 无限搜索 | 搜 4 次还不停，撞上 max_steps | 提示词里硬性规定"最多搜 2 次" + max_steps 兜底 |
| 重复调工具 | 一模一样的搜索查两遍，白烧钱 | `reply()` 里加调用缓存，同参数直接复用 |
| 换行变字符 | 输出里出现字面的 `\n` | 输出后处理，还原成真换行 |

**记忆类**

| 问题 | 现象 | 解决 |
|---|---|---|
| **单一相似度不够用** | 「我家猫不吃饭」搜不到「用户养了只猫」<br>（二字切片"家猫"和"的猫"一个都对不上） | 再加一层**关键字重合**，取两者较大值 |
| **记忆会膨胀** | 同一件事反复记，挤占检索名额、撑长提示词 | 相似度 >0.75 直接拒收，一轮最多记 5 条 |

最后两条是**真实工程问题，教科书上不写**。

## 🔬 一次失败的探索：语音（记录备查）

项目中途尝试过给搭子配一个**川东方言嗓音**，前后试了四家方案，结论是：

> **市面上没有任何商用 TTS 做过「三汇话」音色，
> 连「四川话」都只是带川味的普通话。**

完整调研结果：

| 引擎 | 方言支持 | 结论 |
|---|---|---|
| 微软 edge-tts | 只有东北话、陕西话 | ❌ 无四川方言 |
| 微软 Azure | 有 `zh-CN-sichuan-YunxiNeural` | ⚠️ 免费端口不放，需付费版 |
| 火山引擎 | 有**四川方言男声**（云舟 2.0 / 小天 2.0） | ✅ 可用，但本质是"川普" |
| 火山声音复刻 | 可克隆真人嗓音 | ⚠️ 138 元/音色，且音色一用即锁死 |

**最后为什么关掉了**：

1. 商用"四川话"本质是**成渝片口音的普通话**，词汇和腔调都是标准化的，
   而三汇所在的**达州方言**有自己的一套说法，本地人一听就晓得不对；
2. 真要地道只能克隆真人嗓音，**138 元/音色**，对毕设来说不划算。

**保留的成果**：写了一个"川普发音层"，把要念的字换成能逼出川渝读音的同音字
（你→李、是→四、去→气），让免费引擎也能念出几分川渝味。
代码还在 `voice.py` 里，`VOICE_ENABLED=true` 就能开。

> 这段记录本身也是成果 —— **知道什么路走不通，和知道什么路走得通，都是工程能力。**

## 🌐 关于人设的说明

### 人设来自哪里

三汇蔡徐坤是**渠江边上长大的川东崽儿**：耿直、火热、讲义气、嗓门大，
经典的"嘴硬心软"型——平时怼你怼得凶，你真有事情第一个冲上来。

他的老家是**四川达州渠县三汇镇**：巴河、州河在那儿汇成渠江，
三条水碰头，所以叫"三汇"。镇上叫得响的有三样——
**三汇特醋、三汇彩亭、还有他**。前两样是真有名，第三样是他自封的。

> 这个名字本身就是个梗（"某某地的某某明星"那种自夸）。
> 那第三样怎么办？**第一版写的是"吹完自己认怂"** ——
> 结果他一吹完就找补，像个心虚的推销员，梗全泄了。
>
> 后来想明白了：**谁都晓得他是 AI，找补反而怂。**
> 改成认到底 —— 有人拿这个打趣，他理直气壮地往下接：
>
> > "啷个嘛？三样就是三样噻"
> > "醋和彩亭都是死物，摆起不动，我可是活的噻 —— 你说哪个排面大？"
>
> 而且这事**不能只写在提示词里**：试过写"别说我开玩笑的"，
> 模型反倒把这句话原样学去甩在结尾（**别想大象**）。
> 所以提示词里只写正面的，负面的一律交给程序薅 ——
> 见下面的 `_strip_tail_coverup()`。

### 说话：川东话，得落在川东

人格里的方言不是随便凑的。举个最小的例子 —— 同样是"怎么"，
成都是「**咋个**」，重庆和川东是「**啷个**」。三汇在川东，
所以全项目【只说"啷个"】：人格词表、方言词典、教学技能，三处一起统一。

> 这种词最容易被模型带偏：训练语料里"咋个"多得多，
> 不特意拧一下，它张口就是一股成都味。
> 实测拧完连跑三道题：**「啷个」3 次，「咋个」0 次**。

**光有方言词还不够。** 真正让人听着像本地人的，是他张口就来的那些
地方和事 —— 重庆人说解放碑，三汇人说的是白塔、河坝、码头、
彩亭会、赶场、渠江号子。所以人格里专门写了一节「你嘴里该有的三汇」，
把这些排成清单，并规定**一次带一个，别堆、别硬塞**。

**这个角色的魅力来自夸张的表演欲和耿直，而不是拿任何群体开涮。**

### 关于"不太脏的脏话"

人设里允许它偶尔甩一句三汇人挂嘴边的俏皮话
（"哦豁""格老子""龟儿哦""说个铲铲""扯把子""遭不住"），
但提示词和代码里都钉死了一条铁律：

> **这些词只能用来感叹事情，永远不能对着人说。**

```
✅ "哦豁，这个事情整拐了噻"        ← 感叹事情，要得
✅ "我这个脑壳有点哈戳戳的"        ← 自嘲，要得
❌ "你哈戳戳的" / "你个瓜娃子"      ← 对着人，绝对禁止
```

原因很简单：**喜剧效果来自"这哥们儿太夸张了"，而不是"他在骂人"。**
前者谁看了都乐，后者会让人不舒服 —— 而且一次回复限一嗓子，
多了就不俏皮了，只显得吵。

### 另一条底线

**信息必须真实**：以工具返回的结果为准，绝对不许自己编。
正经事要办明白 —— 闹归闹，不能给错答案。
